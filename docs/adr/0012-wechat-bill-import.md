# 微信账单导入：中性第三类型 + 交易单号去重 + 规则分类 + 手写 xlsx 解析

微信账单导入是设置页数据管理中的批量入库通道：读取微信支付导出的 xlsx 账单文件，把其中真实的收支流水一次性恢复为账目。它与 AI 文字/OCR 截图等逐笔输入相反——一次几十笔，逐笔确认不可行，于是整个流程围绕"批量 + 汇总确认 + 可撤销"设计。五个核心决策需要记录。

**账目类型扩出第三类「中性」，退款记为中性入库，中性交易仍然跳过**：`EntryType` 从支出/收入两种扩为三种。微信账单中的退款（已退款消费行 + 退款收入行）不标记收入也不标记支出，两行都作为中性记录入库——消费行保留"买过什么"、退款行保留"退了多少钱"，完整反映经过且不污染收支统计；今日合计、日历页金额与绿点、图表页全部只算支出+收入，中性一律排除。拒绝的方案是把退款行当收入导入（收入虚高）或整组跳过（记录丢失，用户明确要求"记录必须在"）。账单里充值/提现/零钱通存取/信用卡还款等"中性交易"是自账户间倒腾，既无记录价值又刷屏账本，仍然跳过并报告笔数。中性记录目前只能由导入产生，手动/AI/OCR 记账无法创建；类别用保留名「中性」占位，不参与分类排行。

**用交易单号做唯一去重，新增可空 `sourceRef` 字段**：微信每笔交易有唯一「交易单号」，重导同一文件或相邻月份重叠文件时不能双份入库。`EntryEntity` 加可空列 `sourceRef` 存交易单号并建可空唯一索引（SQLite 对多个 NULL 不冲突，不影响手动账目），导入时命中已有单号的行跳过。Room 版本 2→3 走无损加列迁移，不动已有数据。拒绝的方案是（日期+金额+备注）启发式比对——同一天两笔同额同商户会误判漏判（样例中 4 月 4 日货拉拉就有 10/15/20/40 的近似重复）。sourceRef 的额外红利：撤销本次导入可以按单号集合定位账目，一次删除。

**分类用内置关键词映射，不依赖 AI**：导入是数据管理操作，不能以用户配没配 DeepSeek API Key 为前提。映射表按关键词匹配「交易类型 + 交易对方 + 商品」（交易类型纳入匹配是为了让"微信红包"这类行命中红包类别——对方与商品列都是占位符；如 茶餐厅/烧腊/汤粉 → 餐饮，货拉拉/地铁 → 交通，超市/画材 → 购物，微信红包 → 红包），只映射到已有类别、永不自动建类别，未命中落到「其他」。离线、瞬时、结果确定；代价是生僻商户落「其他」、映射表需要维护，但 v1 固定内置不做编辑 UI。拒绝的方案是 AI 批量分类（依赖 Key + 网络 + 把整份账单发给第三方）和混合方案（最准但最复杂）。

**xlsx 用手写最小解析器，不用 Apache POI**：xlsx 是 zip 包装的 XML，微信账单只用共享字符串表（`xl/sharedStrings.xml`）和单张工作表（`xl/worksheets/sheet1.xml`）。解析器用 `ZipInputStream` + 平台自带 DOM（`javax.xml.parsers.DocumentBuilder`，JVM 单测与 Android 都能跑）读这两个文件，约 200 行、零新依赖；解析出第 18 行列头并校验 11 列是否与预期一致，对不上即优雅报错"无法识别的账单格式"，不崩溃。两个实现细节：条目流先整读进内存再交给 DOM（DOM 会关闭输入流，直接传 zip 条目流会让 `closeEntry` 抛 Stream closed）；交易时间列存的是 Excel 序列日期（如 46140.7908333333 = 2026-04-28 18:58:48），也兼容直接存格式化字符串的版本。拒绝的方案是 Apache POI（Android 上 APK 增重 10MB+、方法数爆炸、R8/D8 兼容坑）和 fastexcel 等 JVM 库（依赖 Android 没有的 StAX）。v1 只支持微信官方 xlsx，CSV 格式待有真实样例后再加——解析层抽出「文件 → 微信行」接口，加 CSV 只是新增一个解析器，行模型与后续流程完全复用。

**流程：选文件 → 汇总确认（含去重预览）→ 一次性入库 → 30 秒批量撤销**：导入不走逐笔确认卡片。确认层展示账单时间范围、支出/收入/中性笔数、分类分布，以及去重预览（本文件将新增 vs 与已有重复，导入前就知道哪些被跳过）；确认后一次性入库，本次实际插入的账目统一挂上「微信」来源标签（首次导入时自动创建，见 CONTEXT.md「来源标签」），snackbar 反馈"成功导入 M 笔、重复跳过 K 笔"并带「撤销」按钮——按本次导入的 sourceRef 集合删除全部账目，窗口 30 秒（批量导入比逐笔删除的 5 秒需要更多反应时间）。撤销只删本次实际插入的单号，重复跳过的是历史导入、绝不误删。不做导入历史列表与来源查看页面。入口放在设置页数据管理区块，与 CSV 导出并排。
