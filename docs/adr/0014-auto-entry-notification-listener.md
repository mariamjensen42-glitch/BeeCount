# 自动记账：NLS 通知监听为主触发 + 复用 DeepSeek 解析 + 确认通知深链 + 持久化去重

自动记账是 v0.0.2 之后的下一个大功能：支付完成瞬间自动记一笔，无需打开 App。设计经过 grill-with-docs 打磨，八个核心决策需要记录。

**触发机制选 NotificationListenerService（通知监听），不用截图检测、无障碍服务或前台服务**：竞品「支付完成瞬间自动记账、无需截图」的主流实现是 NLS——微信/支付宝/银行支付后发的通知本身就含金额与商户，监听通知文本即可。NLS 只读通知文本、不读屏幕内容，记账是其正当用途，隐私叙事比截图方案「所有照片」权限更轻（相册可能含证件照）；可按包名过滤（只留微信/支付宝），其余通知立即丢弃；无障碍服务原「不采用」的三大理由（读屏内容、滥用嫌疑、保活）对 NLS 基本不成立。原截图方案（MediaStore ContentObserver + WorkManager 6h 补扫 + 「所有照片」权限）整体废弃，手动 OCR 入口继续覆盖「其他支付凭证」。与无障碍服务的关键区别（FAQ 用）：NLS 是只读通知文本、无屏幕内容、按包名白名单过滤，系统授权入口也独立（`Settings.ACTION_NOTIFICATION_LISTENER_SETTINGS`）。

**v1 只监听微信 + 支付宝，不做银行 App；支出与收入双向都记**：银行卡支付时同一笔交易会同时产生微信/支付宝通知和银行「消费 xx 元」通知，跨包名去重没有可靠依据（通知文本无统一交易号），监听三家必然重复记账；微信/支付宝之间天然互斥（一笔支付只经一家）。银行文案格式千差万别也是「本地模板维护」问题的重灾区。选这个范围不漏「银行卡支付」场景——在微信/支付宝里用银行卡付款照样出成功通知，漏的只是 POS 刷卡/ATM（低频，手动/OCR 兜底）。收入方向一并纳入：收款到账、收到红包/转账的「你已收款」类通知与支出走同一个闸门和解析器，只是 `type=income`；注意微信「你收到一笔转账」是待收款（可能退回）而「你已收款」是已到账，靠 prompt 指令区分，解析错了有确认卡片拦。

**解析复用 `ParseEntryUseCase`（DeepSeek），不写平台专属正则**：通知文本直接送现有解析器，`isOcrInput` 同款加 `isNotificationInput` 标记、通知时间戳注入为参照日（`ParseEntryUseCase` 现在注入 `currentDate()` 且校验未来日期，需加日期参数）。通知文本与 OCR 文本同类——都是机读噪声文本，要抽金额/商户/类别，与 ADR 0010「AI 容错、不写平台专属正则」同构；微信导入的关键词映射是给结构化表格行用的，对通知文本复用有限，本地正则无现成代码基础且文案一变就要维护模板。代价是每笔支付通知一次 API 调用，单用户量级下成本可忽略。

**确认流程：主动提醒 + 待确认队列**：后台解析成功即发一条 BeeCount 自己的确认通知（「已记：早餐 15 元 · 微信支付，点此确认」），深链打开直接落到确认卡片；不点也不丢——卡片挂进 App 内待确认队列，下次打开 App 可见；前台时直接出卡。需 `POST_NOTIFICATIONS` 运行时权限（API 33+，与 NLS 授权相互独立，设置页各走一遍引导）。拒绝静默队列（零权限但无即时反馈，功能存在感弱、卡片堆积）与免确认直接入库（与 ADR 0002「解析只是草稿、确认才入库」的确认卡片哲学冲突，AI 错账在金钱账上风险高）。确认心智与现有 AI 记账完全一致。

**去重用持久化「已处理通知」键，不做内存去重**：键 = 包名 + notification key + 文本哈希，落库（Room 已有去重表先例），处理前查、命中跳过、按留存期裁剪。键必须含文本哈希——通知原地更新（「支付中 → 支付成功」）key 不变文本变，文本变算新通知；重复投递（系统重发、NLS 重启后重放）则 key+文本都相同正好命中。内存去重在 NLS 被回收重启后失效，是硬伤。

**失败处理分级：闸门静默，解析失败低姿态提示**：无金额/非收支通知在通知闸门（包名白名单 + 金额/关键词模式）处静默丢弃，用户不该被打扰；闸门过了但 AI 解析失败（网络错误、JSON 无效）时发轻量通知「有一笔支付未能自动记账」，点进助手页、输入框预填通知原文，一键重试——避免「用户以为记了其实没记」的信任伤害；同渠道 15 分钟节流防刷屏。API Key 未配置在开关处检查引导，不逐条提示。

**漏掉的支付不自动补救，预防靠 OEM 白名单引导、兜底靠 OCR**：Android 不向第三方暴露通知历史，NLS 只收实时回调、无重放，前台服务也拿不到历史只会耗电——「补扫通知」在技术上不存在。设置页引导用户把 BeeCount 加入各 OEM 电池白名单/自启动提高 NLS 存活率；漏账靠手动 OCR（支付 App 账单页截图，入口已在助手页顶栏）与手动记账兜底。

**入口是设置页单区块「自动记账」，不做独立子页**：总开关 + 两个状态行（通知监听权限未开启 → 点按跳系统授权页；确认提醒权限未开启 → 点按弹权限请求）+ 一行「漏账可用截图记账」说明；首次拨开关走三步引导（授权监听 → 允许通知 → 完成）。总开关关 = 服务不处理任何通知；开但缺前置 = 提示并跳对应设置，不静默。Android 12 及以下无 `POST_NOTIFICATIONS`，对应状态行自动隐藏。用户侧叫「自动记账」，机制术语「通知记账」见 CONTEXT.md。
